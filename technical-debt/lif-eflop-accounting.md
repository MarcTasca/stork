# Simplified LIF EFLOP accounting

## Status

Accepted technical debt. The current implementation is functional and
internally consistent for comparative EFLOP reporting.

## Current convention

`EffectiveFlopsCounter.count_lif_neurons()` combines connection activity and
the resulting neuron work in one logical event bucket. At index `t`, the
recorded destination membrane is the state available before the update
generated by source spikes at `t`.

This convention intentionally groups:

1. the connection operation caused by a source spike; and
2. the destination-neuron operation caused by that propagated update.

It is a logical operation count, not a cycle-accurate trace of Stork's
`evolve_all()` and `propagate_all()` execution order.

## Known limitation

The LIF estimate uses the membrane trace and a Boolean incoming-update mask. It
does not explicitly inspect the persistent synaptic-current state. Consequently,
it is a simplified zero-skipping model and cannot distinguish every case where
synaptic decay remains active without a new incoming spike.

This is acceptable for the current research comparison as long as all compared
LIF runs use the same documented convention and the result is described as an
analytical EFLOP estimate rather than measured runtime, energy, or an exact
hardware instruction count.

## Possible future improvement

A more detailed counter could:

- record the LIF synaptic-state sequence;
- define explicitly whether tensors represent pre-update or post-update state;
- count membrane decay, synaptic decay, integration, input, and reset terms
  independently;
- define how initial and final pipeline boundaries are handled; and
- rerun the SHD notebook before comparing the refined totals with the existing
  convention.

## Acceptance criteria

This item can be closed when:

1. the refined operation rules are written down before implementation;
2. independent hand-calculated traces cover inactive, newly active, decaying,
   spiking, and resetting neurons;
3. the counter and notebook use the same temporal convention; and
4. published EFLOP tables identify which counter version produced them.
